# ADR-003: Arquitetura SPA Separada + FastAPI Backend

**Data**: 2026-06-03
**Status**: Aceito

## Contexto

A interface web da Aurion precisa ser responsiva, atualizada em tempo real e acessível de qualquer dispositivo na rede local. A equipe de desenvolvimento precisa decidir se o frontend será integrado ao backend FastAPI (templates Jinja2 + estáticos) ou separado como uma Single Page Application (SPA) independente.

## Decisão

Adotar uma **SPA separada** comunicando-se com o FastAPI backend via HTTP REST e WebSocket.

### Arquitetura de Comunicação

| Canal | Tecnologia | Propósito |
|-------|-----------|-----------|
| HTTP REST | FastAPI endpoints | Configurações, histórico, envio de comandos, testes de conexão |
| WebSocket | FastAPI WebSocket | Atualizações de estado em tempo real (ouvindo, processando, respondendo) |
| WebSocket | FastAPI WebSocket | Recebimento de áudio da TTS no navegador |

### Stack do Frontend

| Componente | Tecnologia |
|------------|-----------|
| Framework | React 18+ com TypeScript |
| Build | Vite |
| Estilização | Tailwind CSS + design system Pac-Man (CSS existente) |
| Gerenciamento de estado | Zustand ou React Context |
| HTTP client | Axios ou fetch com abstração |
| WebSocket | Native WebSocket API ou ws library |

### Estrutura de Deployment

- FastAPI roda em `http://localhost:8000`
- SPA desenvolvimento: `http://localhost:5173` (Vite dev server com proxy para /api)
- Produção: SPA construída (dist/) servida pelo próprio FastAPI via `app.mount("/static", StaticFiles(...))` ou empacotada junto

## Alternativas Consideradas

### Abordagem B — Jinja2 Templates no FastAPI

**Motivo para rejeição**: Menos flexível para interações complexas em tempo real (chat, indicadores de estado, reprodução de áudio). SPA oferece melhor separação de responsabilidades e capacidade de evolução independente.

### Abordagem C — Juntos com Vanilla JS

**Motivo para rejeição**: Embora mais simples, vanilla JS dificulta a manutenção de estado complexo, gerenciamento de componentes de UI (chat, painéis de configuração, indicadores visuais) e escalabilidade.

## Consequências

### Positivas
- Separação clara entre frontend e backend
- Capacidade de evoluir a SPA independentemente do backend
- Melhor DX com HMR (Vite), tipagem estática (TypeScript)
- SPA oferece experiência mais responsiva e app-like
- Facilita adicionar mais clients no futuro (mobile, CLI)

### Negativas
- Maior complexidade de build e deployment (dois projetos para gerenciar)
- Necessidade de configurar CORS no FastAPI
- Deploy de produção requer build da SPA antes de empacotar
- Contexto de áudio do navegador tem limitações (requer interação do usuário para play)
