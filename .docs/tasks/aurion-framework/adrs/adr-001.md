# ADR-001: Arquitetura Servidor Local + Web App em Tempo Real

**Data**: 2026-06-03
**Status**: Aceito

## Contexto

A Aurion é um gerenciador de voz para o Hermes Agent que precisa rodar localmente no computador do usuário, capturar áudio do microfone, detectar a palavra de ativação "Aurion", enviar comandos para o Hermes Agent e retornar respostas por voz. A interface web deve ser acessível de qualquer dispositivo na rede local.

## Decisão

Adotar uma arquitetura de **servidor local + web app em tempo real** como a base para a Aurion.

O sistema consiste em:
- Um serviço local que roda no computador do usuário e gerencia o acesso ao microfone, detecção de wake word, comunicação com o Hermes Agent e síntese de voz
- Uma interface web responsiva (acessível via navegador de qualquer dispositivo na rede local) para controle remoto, envio de comandos por texto e recebimento de respostas

## Alternativas Consideradas

### Abordagem B — Desktop App + Web Dashboard

Um aplicativo desktop (Electron/Tauri) com acesso direto ao microfone do sistema operacional, mais um web dashboard para controle remoto.

**Motivo para rejeição**: Maior complexidade de desenvolvimento e distribuição (necessita de installer/empaquetamento para cada plataforma), enquanto a abordagem de servidor local é mais simples e atende ao mesmo propósito.

### Abordagem C — Microsserviços Containerizados

Stack completa de microsserviços em containers Docker (wake word, STT, Hermes bridge, TTS, web UI).

**Motivo para rejeição**: Mais pesado em recursos do sistema (CPU, memória, disco) e mais complexidade operacional. Para um assistente pessoal rodando em um único computador, a sobrecarga não é justificada na fase inicial.

## Consequências

### Positivas
- Simples de implantar: um único serviço local
- Privacidade total: todo processamento ocorre no computador do usuário
- Sem dependência de serviços de nuvem externos
- Interface web acessível de qualquer dispositivo na mesma rede
- Baixo consumo de recursos comparado a containers

### Negativas
- Requer configuração de áudio no SO local (permissões, driver)
- Acesso ao microfone depende do navegador/dispositivo onde o comando é dado
- Menos modular que containers — difícil substituir componentes individualmente
