# ADR-002: Stack de Backend Python com FastAPI

**Data**: 2026-06-03
**Status**: Aceito

## Contexto

O projeto Aurion requer um serviço local que opera continuamente no computador do usuário. Este serviço precisa gerenciar acesso ao microfone, detectar wake word, capturar áudio, processar comandos por voz e texto, comunicar-se com o Hermes Agent via HTTP REST, armazenar histórico de interações e servir uma interface web.

## Decisão

Adotar **Python 3.11+ com FastAPI** como framework de backend.

### Componentes do Backend

| Componente | Biblioteca/Framework |
|------------|---------------------|
| Framework web | FastAPI + uvicorn (ASGI) |
| Servidor ASGI | uvicorn |
| API assíncrona | aiosqlite para SQLite |
| Captura de áudio | pyaudio |
| Detecção de wake word | Porcupine (Picovoice) |
| Speech-to-Text (STT) | whisper.cpp com modelo base quantizado Q4/Q5 (ggml-base.bin) |
| Text-to-Speech (TTS) | edge-tts |
| Serialização de dados | Pydantic v2 |
| Configuração | pydantic-settings |
| Gerenciamento de dependências | Poetry ou uv |

### Justificativa

FastAPI oferece:
- Tipagem nativa com Pydantic, reduzindo erros de validação
- Suporte nativo a WebSocket para comunicação em tempo real com a SPA
- Geração automática de documentação OpenAPI/Swagger
- Performance superior a Flask para workloads concorrentes
- Async/await nativo para operações de E/S não bloqueante

Python é a escolha natural porque:
- Bibliotecas maduras para áudio e processamento de voz
- Ecossistema líder em ML/NLP (Vosk, Porcupine, edge-tts)
- Desenvolvimento rápido para prototipagem
- Compatibilidade cross-platform (Windows, Linux, macOS)

## Alternativas Consideradas

### Abordagem B — Go

**Motivo para rejeição**: Embora Go ofereça melhor performance nativa e binários únicos, carece de bibliotecas maduras para processamento de áudio e STT/TTS. Integrar modelos de ML exigiria chamadas a bibliotecas C ou serviços externos, aumentando a complexidade sem benefício proporcional nesta fase.

### Abordagem C — Node.js/TypeScript

**Motivo para rejeição**: Excelente para comunicação em tempo real, mas ecossistema de áudio/STT/TTS significativamente mais limitado. A unificação com o frontend foi rejeitada pelo usuário, preferindo separação clara entre SPA e backend.

## Consequências

### Positivas
- Melhor ecossistema Python para áudio, STT e TTS
- FastAPI facilita documentação automática e testes
- Async nativo para operações concorrentes (escuta + API + WebSocket)
- Deployment simples: `pip install` ou binário com PyInstaller/Nuitka

### Negativas
- GIL limita paralelismo verdadeiro (mitigado por usar async e threads separadas para captura de áudio)
- Performance bruta inferior a Go para computação CPU-intensiva
- Necessidade de gerenciar ambiente Python (venv, pyenv) ou empacotar com PyInstaller
